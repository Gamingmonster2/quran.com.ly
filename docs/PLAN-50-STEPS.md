## كيف تُنفَّذ كل خطوة (دورة ثابتة)

1. **تنفيذ** الخطوة (كود/بيانات/محتوى) في نطاق ملفات محدد.
2. **بناء** (`npm run build`) — يتضمن التصيير المسبق وService Worker تلقائيًا.
3. **فحص آلي في متصفح حقيقي** (حزمة التحقق الخاصة بالمرحلة — Playwright على Chrome).
4. **نشر** على Cloudflare Pages + **تحقق حي** (curl/متصفح على quran.com.ly).
5. **توثيق** النتيجة (تحديث ROADMAP/الوثيقة + لقطات) والالتزام بـ commit واضح.

قاعدة: **لا تُعتبر أي خطوة مكتملة حتى تنجح في الفحص الحي**، وأي خطوة تفشل تُصلح قبل الانتقال.

# الأسبوع 1 — الأساس التقني وSEO (الخطوات 1–7)

**هدف الأسبوع**: تحويل البنية إلى روابط دلالية بالأسماء + جاهزية فهرسة كاملة.
**KPI**: 114 صفحة سورة + 6236 صفحة آية تُخدم على مسارات `slug` جديدة، وبلا أخطاء فهرسة في GSC.

**1. اعتماد الهوية الجديدة** — اختيار اسم الموقع الجديد، وتثبيته في مكان مركزي واحد (`i18n` + SEO + manifest + README) مع شعار/أيقونة favicon مبدئية. المخرج: اسم موحّد في كل الموقع. القبول: فحص آلي يتأكد أن الاسم الجديد يظهر في عنوان الرئيسية وmanifest.

**2. خريطة slugs لكل السور** — توليد `public/assets/data/surahs-slugs.json`: لكل سورة `{id, slugEn (kebab-case من transliteration), slugAr (الاسم العربي), aliases}`. المخرج: ملف بيانات + سكربت توليد + اختبار تطابق 114. القبول: أسماء مطابقة (`al-mujadila`, `ya-sin`, `ali-imran`…).

**3. توسيع الموجّه (Router)** — دعم المسارات: `/{locale}/{slug}`، `/{locale}/{slug}/{ayah}`، ودعم `?startingVerse=N`، مع `/surah/{id}` و`/en/...` القديمة تعمل. المخرج: `router.ts` جديد + اختبارات وحدة. القبول: كل الأشكال تفتح نفس المحتوى الصحيح.

**4. الـcanonical وhreflang** — الروابط الجديدة هي الـcanonical، والقديمة تُبقي نفس المحتوى مع `canonical` للجديد، وhreflang لكل لغة + x-default. المخرج: `seo.ts` محدّث. القبول: فحص آلي لـcanonical على 20 صفحة عشوائية + صفحة آية.

**5. تحديث التصيير المسبق** — توليد صفحات السور والآيات على مسارات slugs الجديدة (مع القديمة) وحجم إجمالي يحترم حدود Cloudflare (20,000 ملف). المخرج: 6,475+ صفحة مسبقة. القبول: فحص عينة من كل نوع + حجم <20k ملف.

**6. الخرائط وrobots وGSC** — تحديث `sitemaps/*` إلى slugs + إبقاء خرائط الآيات + إرسال خرائط الموقع في Google Search Console يدويًا (بحساب المالك). المخرج: 9+ خرائط سليمة. القبول: 200 لكل خريطة + إرسال موثّق في GSC.

**7. تدقيق SEO تقني** — عنوان/وصف فريد لكل صفحة، مراجعة «الصفحات غير المفهرسة» في GSC، إصلاح أخطاء الـcanonical/الـredirect، وإزالة أي محتوى مكرر. المخرج: تقرير تدقيق + إصلاحات. القبول: 0 أخطاء canonical وحمراء فهارس.

# الأسبوع 2 — صفحات الهبوط والاكتشاف (الخطوات 8–14)

**هدف الأسبوع**: بناء أسطح الاكتشاف التي تجعل quran.com يظهر قبل القارئ — ونطبقها لكلماتنا عالية القيمة.
**KPI**: 8 صفحات هبوط مفهرسة، لكل واحدة عنوان/وصف/FAQ/JSON-LD خاص.

**8. صور OG لكل سورة** — توليد 114 صورة (1200×630) باسم وصفي (`al-mujadila-og.png`) + `alt` + `ImageObject`. المخرج: ملفات صور + حقن في التصيير. القبول: 114 صورة 200 مع وسم `og:image` صحيح.

**9. صور OG لأشهر الآيات** — توليد صور لـ«آية الكرسي» والآيات الأكثر بحثًا (~50) + آلية لعرض آية كصورة عند المشاركة. القبول: عينة 10 صور + وسوم.

**10. صفحة آية الكرسي** — `/aya/ayatul-kursi` أو `/surah/al-baqarah/255/ayatul-kursi`: النص + الترجمة + التفسير + فضل الآية (من مصادر موثوقة) + تلاوة + مشاركة + أسئلة شائعة + JSON-LD FAQ. القبول: صفحة مصيَّرة مسبقًا + فحص محتوى.

**11. صفحات السور المشهورة** — `يس`، `الملك`، `الرحمن`، `الواقعة`، `الكهف`، `المزمل`: نفس القالب (نص كامل + تفسير موجز + تلاوة + مشاركة). القبول: 6 صفحات + روابط أحدث/سابق.

**12. آية اليوم** — قائمة منسّقة (365 آية) + اختيار حسب التاريخ + صفحة `/daily` + JSON-LD + إشعار اختياري. القبول: تغيير تلقائي بالتاريخ + صفحة مفهرسة.

**13. آية الأسبوع** — صفحة `/verse-of-the-week` + أرشيف أسبوعي + مشاركة. القبول: مخرجات أسبوعية مرتّبة + صفحة.

**14. الروابط الداخلية الذكية** — توصية بالآيات المشابهة/المواضيعية، «الآية السابقة/التالية»، «السورة التالية»، «آيات مشهورة في هذه السورة»، وشريط تنقّل بين السور. القبول: 20 رابطًا داخليًا على الأقل في كل صفحة سورة بلا كسر.

# الأسبوع 3 — المشاركة والوسائط (الخطوات 15–21)

**هدف الأسبوع**: تميّز مجاني على quran.com: مشاركة بضغطة بلا حساب ولا رصيد.
**KPI**: بطاقة صورة + 5 قنوات مشاركة + embed يعمل على موقع خارجي.

**15. مولّد بطاقة الآية (PNG)** — Canvas: نص الآية بخط المصحف + رقم الآية + السورة + ترجمة اختيارية + علامة مائية للموقع + سمتان (ليلي/بيج). القبول: تنزيل PNG بدقة 1080×1080 و1200×630 وفحص النص المرسوم.

**16. تحرير/معاينة البطاقة** — خيارات (خط، حجم، مظهر، إظهار الترجمة، تنسيق) + معاينة حيّة. القبول: 6 خيارات تعمل بلا أخطاء.

**17. أزرار المشاركة** — واتساب، X، فيسبوك، تلغرام، نسخ رابط/نص بالمرجع (`[سورة البقرة: 255] quran.com.ly/...`). القبول: فحص الروابط المولّدة لـ4 منصات.

**18. Web Share API** — مشاركة أصلية على الجوال (نص/رابط/ملف PNG عندما يدعم المتصفح). القبول: فحص على محاكي جوال + سلوك احتياطي.

**19. مسار Embed** — `/embed/{locale}/{slug}/{ayah}?theme=...` يظهر محتوى مصغّرًا (آية + ترجمة + شارة الموقع) + زر «نسخ كود iframe» + توثيق. القبول: فتح المسار + iframe يعمل في صفحة اختبار.

**20. نسخ الآية بتنسيقات** — نسخ كنص عربي، عربي+ترجمة، JSON، HTML مع الإسناد. القبول: 4 تنسيقات صحيحة في الحافظة.

**21. صفحة الأدوات `/tools`** — تجمع: بطاقة آية، embed، آية اليوم، تنزيل البيانات. القبول: صفحة مفهرسة + روابط تعمل.

# الأسبوع 4 — تجربة القراءة المتقدمة (الخطوات 22–28)

**هدف الأسبوع**: سدّ فجوة «تجويد ملوّن + تفاسير + مصحف صفحات» التي لاحظتها في quran.com.
**KPI**: وضع تجويد + 3 تفاسير + 5 ترجمات + وضع صفحات يعمل على الجوال وسطح المكتب.

**22. بيانات التجويد الملوّن** — جلب «Uthmani Tajweed Script» لكل آية (API مفتوح) وتخزينه JSON مضغوط بحسب السورة عند البناء. القبول: 114 ملفًا/1 ملف موحّد مع تحقق 6236 آية.

**23. عرض التجويد + المفتاح** — تحويل الوسوم إلى spans ملوّنة + مفتاح ألوان وتعريف القواعد + toggle + تجربة RTL/خطوط. القبول: مقارنة بصريّة + عدم كسر النص الصحيح.

**24. تعدد التفاسير** — إضافة تفسيرين إضافيين (بحسب التراخيص المتاحة) + مفاتيح + تحميل كسول. القبول: 3 تفاسير قابلة للتبديل لكل آية.

**25. تعدد الترجمات** — أهم 5 لغات (fr, ur, id, tr, es) بيانات ثابتة + قائمة تبديل + حفظ التفضيل. القبول: كل ترجمة تُحمّل عند الطلب (0 طلبات قبل التفعيل).

**26. الترجمة الصوتية (Transliteration)** — نص لاتيني لكل آية + toggle في القارئ. القبول: عرض صحيح مع RTL للنص القرآني.

**27. وضع المصحف بالصفحات** — خطوط QCF (604 صفحة) بتحميل كسول + تنقّل صفحة/جزء/حزب + تحديد بداية القراءة. القبول: 604 صفحة قابلة للوصول، لا تحميل لخطوط غير معروضة، أداء جيد على الجوال.

**28. تحسين الكلمة-بكلمة** — النقر على كلمة => معناها/جذرها/موضعها + تظليل الكلمة أثناء التلاوة إن توفرت بيانات التوقيت. القبول: نقر يعمل لكل كلمة + تزامن صوتي.

# الأسبوع 5 — عمق المحتوى والتعلّم (الخطوات 29–35)

**هدف الأسبوع**: توسيع سطح الكلمات المفتاحية بالمحتوى، كما يفعل quran.com بصفحات `/info` و`/explore`.
**KPI**: 114 صفحة معلومات سورة + 20–30 صفحة موضوع + بحث متقدم.

**29. معلومات كل سورة** — صفحة `/{locale}/{slug}/info`: مقدمة تفسيرية موجزة (من مصدر مفتوح/مُرخّص)، فضائل، عدد، نوع، جزء، محاور. القبول: 114 صفحة مصيَّرة + عناوين فريدة.

**30. فهرس المواضيع `/explore`** — 25–50 موضوعًا (الصبر، الرحمة، الصلاة، الأخلاق…) مع آيات مرتبطة بوسوم. القبول: صفحات مواضيع + روابط آيات.

**31. صفحات الأدعية من القرآن** — تجميع أدعية قرآنية بآياتها + مشاركة. القبول: 30–50 دعاءً مفهرسًا.

**32. القرآن في عام `/calendar`** — خطة قراءة مقسمة (يوم/أسبوع/شهر) مع تتبع محلي. القبول: خطة كاملة قابلة للتتبع.

**33. قوائم القراءة** — إنشاء قائمة سور/آيات محلية + مشاركة/تصدير. القبول: CRUD محلي يعمل بعد إعادة التحميل.

**34. بحث متقدم** — فلاتر (سورة/جزء/مكية-مدنية/نوع المحتوى)، ترتيب، اقتراحات، تاريخ بحث، ونتائج كاملة للآية. القبول: 6 فلاتر تعمل + أداء <100ms.

**35. صفحة المطورين `/developers`** — توسيع توثيق API: النقاط، CORS، أمثلة (curl/JS/Python)، حدود، ترخيص. القبول: صفحة مفهرسة + أمثلة صحيحة.

# الأسبوع 6 — الحسابات والمزامنة (الخطوات 36–41)

**هدف الأسبوع**: إضافة طبقة الحساب كما لدى quran.com، مع بقاء الموقع يعمل محليًا بلا حساب.
**KPI**: تسجيل دخول Google + مزامنة عبر جهازين + صفحة بياناتي/خصوصية.

**36. تهيئة Supabase** — مشروع مجاني + Auth (Google/بريد) + مفاتيح عامة فقط في الواجهة. القبول: تسجيل دخول/خروج يعمل على الحي.

**37. مزامنة العلامات والتقدم** — local-first ثم مزامنة عند الدخول (دمج بلا فقدان). القبول: فحص جهازين (سياقين) يتشاركان نفس البيانات.

**38. أهداف القراءة والـstreak** — هدف يومي/أسبوعي + إحصاءات بسيطة. القبول: عرض/تحديث الهدف عبر الجهازين.

**39. الملاحظات/التدبرات الشخصية** — ملاحظة لكل آية + تصدير/حذف. القبول: إنشاء/تعديل/حذف + مزامنة.

**40. مزامنة التفضيلات** — القارئ/الخط/السمة/اللغة/الترجمة عند الدخول. القبول: تُسترجع على جهاز آخر.

**41. صفحة حسابي والخصوصية** — عرض البيانات، تصدير JSON، حذف الحساب، وسياسة خصوصية محدثة. القبول: حذف كامل للبيانات + صفحة خصوصية.

# الأسبوع 7 — التوسع اللغوي والأداء والرصد (الخطوات 42–47)

**هدف الأسبوع**: مضاعفة سطح الكلمات المفتاحية بـ5 لغات + قياس وتحسين.
**KPI**: 7 لغات واجهة، hreflang/خرائط لكل لغة، Lighthouse SEO ≥95 وCWV خضراء.

**42. 5 لغات واجهة إضافية** — fr, ur, id, tr, bn (قواميس + RTL/LTR + تبديل + حفظ). القبول: كل لغة تعرض واجهة سليمة بلا مفاتيح ناقصة.

**43. SEO لكل لغة** — عناوين/أوصاف/خرائط/hreflang لكل لغة، مع بدائل x-default. القبول: فحص hreflang على 7 لغات + خرائط سليمة.

**44. ترجمات قرآنية للغات الجديدة** — بيانات ترجمة موثوقة مرخّصة + محمّل لكل لغة. القبول: ترجمة تعمل لكل آية في كل لغة.

**45. الأداء** — تحسين الصور (WebP/AVIF)، تقسيم الحزم، تحميل الخطوط، Critical CSS، قياس Lighthouse على الجوال وسطح المكتب. القبول: SEO≥95، LCP<2.5s، CLS<0.1.

**46. التحليلات والرصد** — Cloudflare Web Analytics (بلا كوكيز) + لوحة أخطاء + تقرير أسبوعي للكلمات/الزيارات. القبول: بيانات تصل + تقرير أول.

**47. إتاحة نهائية** — فحص WCAG مبسط لكل الصفحات الجديدة + دعم لوحة المفاتيح + تباين الألوان للسمتين واللغات. القبول: 0 أخطاء حرجة في الفحص.

# الأسبوع 8 — الفيديو والتدقيق النهائي (الخطوات 48–50)

**هدف الأسبوع**: ميزة الفيديو (بديل مجاني لأداة quran.com) + إغلاق الشهر بتدقيق شامل.
**KPI**: فيديو آية يعمل في المتصفح + 100+ فحص آلي ناجح + تقرير إنجاز.

**48. فيديو آية في المتصفح** — Canvas متحرك (نص الآية + ترجمة + علامة مائية) + التلاوة الصوتية + MediaRecorder وتنزيل WebM/MP4، مع فحص CORS للصوت وحل بديل (تسجيل صوتي بدل التلاوة عند القيود). القبول: فيديو 15–30 ثانية يُنزَّل ويعمل على جوال.

**49. صفحة الأدوات النهائية + تحسين المشاركة** — دمج البطاقة/الفيديو/embed/آية اليوم في `/tools` + قوالب جاهزة للنشر (واتساب/X) مع شارة الموقع. القبول: كل الأدوات تعمل من صفحة واحدة.

**50. التدقيق النهائي والتقرير** — حزمة فحص شاملة (100+ فحص حي)، تقرير Core Web Vitals، مراجعة GSC، جرد الميزات مقابل quran.com، وتحديث خطة الشهر التالي. القبول: تقرير منشور + كل الفحوص خضراء + نشر ناجح.
